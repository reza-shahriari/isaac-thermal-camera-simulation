Site gallery

The gallery's media cache, which decides what gets re-encoded and what gets republished.

tests/unit/test_site_gallery.py on GitHub

make site re-encodes 55 clips and stills from outputs/, so it caches. The cache is the part worth testing: every stale answer it gives is published, and a published clip that does not match the manifest is worse than a missing one, because nothing about the page says it is wrong.

The failure this pins actually happened. A build that changed the encoder defaults and added per-item overrides in one go left a 29 MB, 1280-pixel clip on disk under a cache entry claiming 720 pixels; every later build trusted the entry, skipped the re-encode, and republished the file the manifest no longer described.
