Roadmap row length

RP.9 — the row-length lint the roadmap says enforces it.

tests/unit/test_roadmap_row_length.py on GitHub

Revision 3 of the plan held 224,508 of its 298,272 characters inside markdown table cells, averaging 1,234 per row with a 4,958-character maximum. Rows that size are a second changelog: unrenderable, unreviewable as a diff, and unmergeable between two sessions without a manual rewrite — which is how four subsystems came to be over-reported and how a whole-file write silently reverted committed work.

Revision 4 states the fix in its own prose: "Step rows are capped at 600 characters and ledger rows at 200, enforced by a parser in make check (RP.9)." This is that parser. Until it existed the cap was a sentence, and a sentence is what revision 3 had too.

Scope, because a lint that creeps is a lint that gets disabled. Step tables and the shipped ledger only — never prose, never the generated Do next block, never the phase or risk tables. A paragraph is allowed to be a paragraph; the cap exists because a table cell is the thing that does not diff.

This is a lint, not a physics verification, and is not counted as one.

The ledger's own 200-character cap has an owner already (test_shipped_ledger.py, RP.6) and is not duplicated here; this file owns the 600 and the self-test that proves the parser catches rather than merely passes.
