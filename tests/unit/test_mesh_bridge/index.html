Mesh bridge

WM.3 — a mesh temperature field reaching the pixels of a curved prim.

tests/unit/test_mesh_bridge.py on GitHub

WM.2 put a field on a triangle mesh; this is the bridge that feeds it a face and a barycentric pair per pixel, so a wheel, a tyre or an exhaust pipe stops being one temperature — the case ADR 0087 lists as Hard.

The claims:

  • Warp's mesh_query_point_no_sign and the brute-force NumPy oracle agree on the face and on the sampled temperature for 100 % of pixels on a curved fixture. The oracle is not an optimised twin: it tests every triangle.
  • A prim with no binding keeps the per-instance value bit-identically, so attaching the bridge to an existing scene changes nothing until a mesh field is authored for something in it.
  • A pixel further from the bound mesh than the tolerance raises rather than snapping to the nearest cell.

docs/physics-model.md §13.1; ADR 0087 (and its WM.1 addendum), ADR 0014; roadmap WM.3.
